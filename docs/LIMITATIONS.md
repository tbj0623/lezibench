# LIMITATIONS — 局限与诚实边界

> 这份文件回答一个问题：**LeziBench 测不了什么。**
> 每条都是这套设计的直接后果，不是「以后会改进」的客套话。有些是权衡，有些是永久边界。

---

## 0. 一句话

> LeziBench 测量的是「按这套公开规则，这一次做得怎么样」，
> **不是**「这个模型客观上有多聪明」。
> 它是一份体检报告，不是学位证书。

---

## 1. 题库是公开的，可以被读

### 1.1 事实

16 道题的题面生成逻辑、评分条件、判分器、甚至标准答案的推导方式，全都在 `src/` 目录里，
用任何文本编辑器就能读：

```
src/exam/items/instruction.mjs   # 指令理解 4 题（含 publicCriteria 与 oracle）
src/exam/items/reasoning.mjs     # 逻辑推理 4 题
src/exam/items/data.mjs          # 信息整理 4 题
src/exam/items/correction.mjs    # 状态追踪与纠错 4 题
src/grading/grade.mjs            # 判分器
src/grading/parse.mjs            # 答案解析与归一
scripts/oracle-answers.mjs       # 标准答案生成器（给开发者做回归测试用）
```

### 1.2 这是有意的

一个不能看的评测，你没法判断它到底在测什么，也没法在你觉得判错的时候去核对。
闭源评测的「权威感」来自不透明，而不是来自正确。

### 1.3 但是代价必须说清楚

- **模型可能对题面有记忆优势。** 如果训练数据读过这个仓库，某些题的分数会偏高。
- **任何人都可以改题、改判分器、改答案文件。** 改了当然能拿高分，但那份分数只对改的人有意义。
- **所以这里没有「防作弊」这个概念。** 我们不做，也不宣称做。

> 换句话说：LeziBench 的分数可信度，建立在「你没改它」这个前提上。
> 这是一个**自测工具**的合理前提，但不是一个认证机构能接受的前提。

## 2. 不是认证，不防作弊

每一份报告自己就印着 `本地规则核验 · 非认证成绩（LOCAL_SELF_TEST）`。

| 缺什么 | 具体含义 |
|---|---|
| **没有第三方见证** | 判分发生在你自己的机器上，没有可信第三方能证明这份成绩是真跑出来的 |
| **没有身份核验** | 没有登录、没有账号、没有签名。谁都能跑，也谁都能声称某个分数是自己的 |
| **没有被测对象锁定** | 报告不记录「是谁在答题」，也不验证答案是否由被测模型产生 |
| **没有排行榜** | 没有中心服务器就没有共同基准；做了排行榜也只是一个可以随意提交的列表 |

如果你需要的是「可用于对外宣称的能力认证」，这个工具解决不了你的问题。
它给出的是一份可以自己核对的能力体检报告。

## 3. 16 题覆盖不到的东西

四个维度、十六道题，覆盖面是**刻意收窄**的：只测「给定材料、给定规则、要求产出结构化答案」这一类任务。

| 能力 | 为什么测不到 |
|---|---|
| **长上下文** | 单题材料最长约 1200 字（当前最长的 D04）。真实场景里「两万字文档里找一处矛盾」这类能力，这里没有对应题目。 |
| **多轮工具调用** | 整套题是「一次作答、一次判分」，没有需要连续调用工具、根据返回值调整策略的任务。 |
| **代码工程能力** | 没有需要读仓库、改代码、跑测试的题。C04 只是看一段十行的伪代码，不是工程任务。 |
| **开放式写作与审美** | 判分是确定性代码，只能判「可形式化的对错」。文风、结构、说服力没有判据。 |
| **事实准确性 / 幻觉率** | 题目自带全部事实，不需要模型调用外部知识。所以它不测「知不知道」，只测「给了材料用得对不对」。 |
| **安全性与拒答** | 没有对抗性输入、没有越狱尝试、没有需要拒绝的请求。 |
| **多语言能力** | 题库全部为中文。非中文能力不在覆盖范围内。 |
| **推理深度上限** | 最难的一题是 R04（六人六色座位推理，线索全部是关系型/否定型，不允许直述）。搜索空间是 6! 量级，**不需要**多步搜索、也不需要写代码求解；它不区分「能做」和「能做得很深」。 |
| **规划与自主性** | 题目由外部逐批下发，被测对象不需要自己拆解任务、安排顺序、决定何时停止。 |
| **长期一致性** | 一局只有 16 题、几分钟。它不测「跑一整天之后是否还稳定」。 |

### 3.1 一个更隐蔽的边界

因为题目是**模板化生成**的（同一道题每次只换数字和名字），
所以它测的是「在同一类任务上稳不稳定」，而不是「面对陌生任务时能不能迁移」。

一个模型可能把 16 种题型都练熟，但在没见过的任务形态上完全失灵 —— 这份试卷看不出来。

## 4. 什么样的比较没有意义

下面这些比较，做了也是白做，甚至会得出错误结论。

### 4.1 跨题库指纹比较 ✗

**两次运行可比，需要同时满足：`examVersion` 相同、`graderVersion` 相同、`catalogFingerprint` 相同。**

`catalogFingerprint` 是对每道题的
`{id, dimension, difficulty, points, batch, criteria{id,points,text}, probes{prompt, criteria}}`
算的 SHA-256 —— 评分条件或探针 seed 下题面的任何变化都会改变指纹。

**特别注意：`examVersion` / `graderVersion` 相同 ≠ 可比。** 版本号是人手动升的，可能漏升；
指纹是内容算出来的，不会漏。我们在自己的真实实测里就遇到过：某一批运行的版本号全是 `1.0.0`，
但题库与评分条件实际改过，指纹随之变化。

**但指纹也不是万能的：** 题面探针只用几个固定 seed。
「指纹相同」只保证「那几个探针 seed 下的题面 + 全部评分条件」相同，
**不能**保证所有 seed 的题面都逐字相同。某个随机分支没被探针触发时，改题面可能不改变指纹。
这是概率性覆盖，读报告时请知道这个边界。

还有一层：如果两次运行的指纹是**不同算法版本**算出来的（算法本身升级过，例如加进了题面探针），
那两个数值**不可直接比较** —— 这时只能靠版本号判断。

判断方法：先比 `examVersion` 与 `graderVersion`，再比报告里印的 `题库指纹`。

### 4.2 不同温度 / top_p / 采样参数之间比较 ✗

同一模型在 `temperature=0` 和 `temperature=1` 下是两种不同的行为模式。
前者稳定但可能错过需要探索的路径，后者方差大。

把两次运行的分差直接归因于「模型能力」是错的。要比较就先固定采样参数，
并且**各跑多次取分布**，而不是比单次结果。

### 4.3 不同工具配置 / 系统提示之间比较 ✗

有没有联网、有没有代码执行、系统提示怎么写、上下文里塞了什么，都会影响结果。

一个开了工具的 Agent 和一个裸模型跑同一套题，分数不可直接比 —— 这不是同一种被测对象。

### 4.4 单次运行之间比较 ✗

每局题目由 seed 生成，题面数据不同。单次运行的分数有随机性，一两分的差距完全可能在噪声范围内。

**要比就多跑几局看分布。** 任何「某一局拿了多少分」的说法都只是**单次样本**，
不是这个工具的预期分，更不是某个模型的稳定能力值。

### 4.5 和别的评测的分数换算 ✗

LeziBench 的 80 分和任何其他评测的 80 分没有对应关系。
满分 100 不代表它是百分比，也不代表它和某个「通过线」挂钩。

### 4.6 用段位代替分数 ✗

段位只是把总分切成五段的标签。「良好」是 65–79 分，一个 65 分和一个 79 分同属「良好」，
但能力差距可能很大。看分数和逐题理由，不要只看段位。

## 5. 耗时不是能力指标

报告里有一项「实测耗时」，它是从 `start` 到最后一批评分完成之间的墙上时钟时间。
这个数字受以下因素影响，且这些因素**都不是被测模型的能力**：

- 宿主机性能、当前负载、磁盘速度；
- 模型 API 的网络往返与排队；
- Agent 框架本身的开销、重试策略、上下文长度；
- 作答时是否先去查了资料、跑了工具。

**不要用耗时给模型排名**，也不要把耗时和分数拼成一个「性价比」指标。
这个字段的用途只有一个 —— 让你知道这次跑了多久。

## 6. 确定性判分的代价

选择用代码判分而不是用模型判分，换来的是可复现和可审计，代价是判分只能覆盖可形式化的部分。

### 6.1 格式不对可能被判成「待复核」

如果答案里有内容但一个字段都识别不出来，这道题会进入 `UNPARSEABLE`，
整局降级为 `PARTIAL`、不给段位。

这比误判成 0 分更诚实，但也意味着**格式规范本身成了一道隐性门槛**。

### 6.2 同义表述覆盖不全

别名表是显式列举的，没列进去的等价说法不会被认。
这是「不猜」的代价：宁可判待复核，也不猜你的意思。

### 6.3 题目必须能被形式化

凡是没法写成「通过 / 不通过」的任务，都进不了这个题库。
这直接导致了 §3 那一整张表。

### 6.4 用「散文」作答会比用 JSON 更容易失分

判分器支持「key: value」行格式和若干 NL 兜底规则，但**结构化 JSON 永远是最稳的**。
这是格式偏好，不是能力偏好 —— 如果你在测「模型能不能自己决定输出格式」，这份试卷会干扰这个结论。

## 7. V1 版本的具体边界

当前版本以 `package.json` 的 `version` 为准（引擎版本以 `node scripts/cli.mjs version` 为准）。已知的具体限制：

| 限制 | 说明 |
|---|---|
| **只有 standard 一种模式** | 传入其他模式会明确报错，不会静默降级 |
| **客户端可改** | `state.json`、答案文件、判分器都在本地，没有签名校验 |
| **只有中文** | 题库、理由、报告都是中文 |
| **只有 16 题** | 没有题库轮换，同一模型重复跑会积累熟悉度 |
| **已判分的批次不可覆盖** | 答案写错了只能新开一局，不能就地重答 |
| **无并发保护** | 两个进程同时对同一 `runId` 提交，行为未定义（原子写保证文件不损坏，但不保证逻辑顺序） |
| **平台验证不完整** | 只有 DSH 与 Windows 真机跑通过；macOS / Linux 有实现但未跑完整局；OpenClaw / Codex 完全未核实 |
| **npm bin / npx 未实测** | `package.json` 声明了 `bin`，但 `npm install` / `npm link` / `npx` 三种调用方式都没有实际执行过 |
| **题库指纹不防篡改** | 指纹能发现「题库变了」，但不阻止有人改了题库再改代码里的指纹 |

平台详情见 [COMPATIBILITY.md](COMPATIBILITY.md) 与网站「支持环境表」。

## 8. 「背答案能拿多少分」——实测基线

> 这一节回答一个很实际的问题：**不读题面、只给固定答案，能拿多少分？**
> 结论先说：**个位数。背答案拿不到分。**
> 但我们仍然**不把「防作弊」当卖点** —— 原因见 §8.4。

### 8.1 整体上限：固定答案能拿多少

用「完全不读题面、只给固定答案」的策略，各跑 **400 个 seed** 取平均总分（满分 100）：

| 策略 | 平均总分 |
|---|---:|
| 每题都填第一个选项字母（`A` / `R1` / `true` 等） | **约 5.0** |
| 每题都答 `C`（不确定） | **约 1.3** |
| 全部填 `0` | **0.00** |
| 全部填空对象 `{}` | **0.00** |

**闭着眼睛瞎答，稳定在个位数。** 靠背答案拿高分这条路走不通，真正拿高分必须逐题读题面。

### 8.2 照抄题面里的示例，也一样拿不到分

题面里会给出输出格式示例（JSON 骨架）。我们测了「把题面里最后一个可解析的 JSON 示例原样提交」：

**16 道题、每道 200 个 seed，平均得分全部为 0。** 没有任何一道题能靠照抄示例得分。

### 8.3 关于 `D02`：一个容易误读的现象

`D02` 是三选一（A / B / C）。如果固定提交 `{answer:'C', reason:'…无法确定。'}`，
大约 **1/3 的 seed 上会拿满分**。**这看起来像漏洞，其实不是。**

我们做了归因实验（600 个 seed）：

| 分组 | seed 数 | 模板满分次数 | 条件命中率 |
|---|---:|---:|---:|
| 真实答案为 `C` 的 seed | 195（32.5%） | 195 | **100%** |
| 真实答案不是 `C` 的 seed | 405 | **0** | **0%** |

也就是说：**模板只在「C 本来就是正确答案」的那些 seed 上得分，答案不是 C 时一分不给。**
这 1/3 是三选一题型的**结构性下限**，不是判分缺陷 —— 任何三选一的题，瞎选一个都有 1/3 概率撞对。

进一步的证据：在真实答案**不是** C 的 193 个 seed 上，只答 `C` 且不写理由，
平均得分是 **0.00 / 6**，逐条件统计也没有任何条件给分 —— 不存在「答错也白给部分分」。

> 反作弊回归测试 `evidence/antileak.test.mjs` 里对应的断言判据就是
> 「命中率不得显著高于 1/3」（阈值 45%），而不是「必须为 0」。
> 把「必须为 0」当判据是错的：三选一题型在前者下永远不可能通过。

### 8.4 那为什么仍然不宣称「防作弊」

上面三条说明**背答案拿不到分**，但**不等于这个工具「防作弊」**，原因是另一类问题：

- **题库、评分条件、判分器全是公开源码。** 任何人可以读题、读条件、甚至改判分器。
- **客户端可改。** `state.json`、答案文件都在本地，没有签名校验（见 §7）。
- **16 题固定。** 同一模型重复跑会积累熟悉度。

所以准确的说法是：**「背答案没用」是成立的；「防作弊」是不成立的。** 这两件事不一样。
如果你需要的是后者（防作弊的严格评测），这份题库不适用 —— 见 §1「题库是公开的，可以被读」。

### 8.5 怎么自己复核这一节

## 9. 如果要用这份成绩对外说点什么

请至少带上三件事：

1. **总分**（以及四个维度分）；
2. **`examVersion` / `graderVersion` / `catalogFingerprint`**；
3. **「本地公开题库自测，非认证，不防作弊」**。

少了任何一项，这份成绩就变成了它本来不是的东西。
