# 这份跑分到底能测出什么（以及测不出什么）

> 这份文档不讲卖点，只讲**边界**。如果你要拿 LeziBench 做能力判断，请先读完。

---

## 1. 一句话结论

**LeziBench 测的是「按明确要求把一件事做对」的能力，不是「智能水平」。**

它擅长暴露：漏读条件、算错数、状态追踪丢步、忽略例外、漏看一行数据。
它不擅长（也无意）衡量：创造力、开放任务规划、工具使用、多轮协作、真实工程判断。

所以：

- **低分是真信号** —— 说明你在某个可复核的细节上确实错了，报告会指出是哪个条件。
- **高分说明不了太多** —— 说明你把 16 道题都做对了，仅此而已。

---

## 2. 为什么 v1.2.0 会被「轻松考满分」

这不是猜测，是实测。我们对 v1.2.0 的 16 道题做了结构量化：

| 指标 | v1.2.0 实测 | 说明 |
|---|---|---|
| 平均题面字数 | **346 字** | 大约是「读完一条微博」的量 |
| 平均数据行 | **2.8 行** | 表格类题目只有 3 行数据 |
| 平均条件算子 | **3.0 个** | 整题只有 3 处需要判断的地方 |
| 平均数字 | **12.8 个** | 需要处理的信息量 |
| 最深的搜索空间 | **4! = 24 种排列** | 座位推理只有 4 个人，可以在脑内穷举 |

**结论：这一版测的是「细心」，不是「能力」。** 一个能认真读完 350 字的模型当然拿满分。
所以那个 100 分**不代表模型强，只代表题太浅**。这个判断我们在 README 里也写明了。

同类问题的三个具体例子（都是真实存在过的缺陷）：

1. **R02 的答案曾经恒定** —— 5 个步骤的代号永远是 `A→B→C→D→E`，直接抄 `ABCDE` 就是满分 30/30。
   靠读代码看不出来，跑 60 个 seed 才暴露。
2. **D02 的答案曾经恒为 C** —— 三个选项里 `C` 永远正确，不看题也行。
3. **I03 的白名单曾经是死规则** —— 写了 A/B 两级白名单，但扫 3000 个 seed 没有一个样本触发过。
   「看起来有 8 条规则，实际只有 5 条起作用」这类问题必须靠跑分布才能发现。

## 3. v1.3.0 改了什么

同样口径重新量化：

| 指标 | v1.2.0 | v1.3.0 | 变化 |
|---|---|---|---|
| 平均题面字数 | 346.5 | **651.2** | 1.9× |
| 平均行数 | 13.4 | **25.8** | 1.9× |
| 平均数据行 | 2.8 | **6.9** | 2.5× |
| 平均条件算子 | 3.0 | **5.5** | 1.8× |
| 平均数字 | 12.8 | **31.0** | 2.4× |

变化最大的几题（不是「变长」，是「变难」）：

| 题 | 变化 |
|---|---|
| `R01` | 2 个商品行 → **6~8 行**，每行不同促销（第 2 件半价 / 限购 / 满额包邮），优惠券有**封顶**。4.0× |
| `D01` | 10 行名单 → **28~35 行**，含空行、全角空格、大小写混用等脏数据，去重后按**双键排序**。3.3× |
| `R03` | 3 种餐盒（可穷举）→ **6 种模块的背包**，**贪心会选错**，必须精确求解。2.0× |
| `I01` | 4 条通知 → **8 条**，含「第 4 条作废第 3 条」「按场次条件生效」「只改格式的噪声条」 |
| `I02` | 9 个商品 → **24 个 + 3 条豁免**，其中一条豁免**被后来的通知否定** |
| `I04` | 4 条指令 → **9 条**，含**检查点快照**、条件触发、**从检查点回滚**、覆盖语义 |
| `C02` | 4 步流水 → **10 步台账**，含两次作废、**撤回的撤回**、调拨（合计不变但分仓变） |
| `C04` | 1 个 bug → **2 个 bug 互相掩盖**，只修一个拿不到满分 |
| `D04` | 3 级 6 人 → **5 级 14 人**，例外链 + 边界值（恰好达线 / 差 1 分） |

还有一个质量提升值得单说：**`R04` 现在是零「直述」线索**。
v1.2.0 的座位推理有大量「X 坐在 N 号位」这种直接抄写的线索；
v1.3.0 改成 6 人 6 色、**全部线索都是关系型或否定型**（「A 比 B 靠前」「C 与 D 相邻」「E 不在两端」），
且每个 seed 都用 518400 次穷举验证过**解唯一**。

## 4. 仍然测不出来的东西（这部分我们没有修，短期内也不打算靠加题解决）

诚实列出来：

### 4.1 出题人、答题人、判分人是同一个系统

我设计了这 16 道题，也参与过答题和判分。**这不构成独立验证。**
缓解手段是：所有评分条件公开可审计、判分器是纯函数（无 LLM 参与）、
正确性由**50 条人工手算夹具**兜底（不是由 oracle 自证）。
但这只保证「判分没有逻辑错误」，不保证「题目难度恰到好处」。

### 4.2 评分条件是公开的

任何人（包括被测模型）都能读到 44 条评分条件的原文。
我们做了两件事让「读条件」不能直接换算成「抄答案」：

- 条件文本**只描述「什么算对」，不描述「怎么找答案」**，不含具体数值
  （曾有 `I01.C1` 写成「不得沿用第 1 条的原始日期或中午 12 点」—— 等于把陷阱直接点破，已删除）。
- 有自动检查扫描全部 44 条条件，禁止出现 `不得 / 不要 / 而非 / 注意` 这类点破词和具体数值。

但**知道评分维度仍然有帮助**，这是公开评分标准无法避免的代价。

### 4.3 完全没有「工具使用」这条轴

16 道题全部是「读文字 → 推理 → 输出 JSON」。没有一道要求调 API、读文件、跑命令。
这是已知的能力覆盖缺口 —— 对比同类产品「虾跑分」，它的 16 题里有 2 道明确要求调用 HTTP 接口取数。

> 如果要补这条轴，需要改产品契约（现在是 16 题 / 4 维 / 100 分），属于 v2 范畴，不在 v1.3.0 内。

### 4.4 固定 16 题，跨版本可比性有限

题目集合是固定的 16 个 id，靠 seed 换皮。跨版本（v1.2.0 → v1.3.0）题面变化很大，
**分数不可跨版本比较** —— 每份报告都印了 `examVersion` 和 `catalogFingerprint`，
请只和同指纹的分数比。

## 5. 第三方验收协议

v1.3.0 的加固效果**不由作者自证**。请按下面流程独立验收。

### 5.1 环境准备

```bash
git clone https://github.com/tbj0623/lezibench.git
cd lezibench
node --version        # 需要 >= 18
node --test tests/*.test.mjs        # 期望：203 pass / 0 fail
```

如果测试不是全绿，**直接判定不通过**，不用继续。

### 5.2 校验指纹

```bash
node --input-type=module -e "import('./src/exam/manifest.mjs').then(m=>console.log(m.catalogFingerprint()))"
```

期望 `6e24cad28bd680c4…`（v1.3.0）。如果不是这个值，说明代码与文档不一致。

### 5.3 独立跑一场真实考试

用你自己的模型，**不要用 `scripts/oracle-answers.mjs`**（那是标准答案生成器，用来验证判分器，不是能力测试）。

```bash
node scripts/cli.mjs start --seed <你的随意字符串>
# 按提示逐批作答，答案写成 JSON 文件后 submit
node scripts/cli.mjs report --run <runId>
```

### 5.4 怎么判断结果（重点）

**不要只看总分。** 按这三条判：

| 观察 | 含义 | 判定 |
|---|---|---|
| 分数 < 100，且报告里有**具体**的失败条件（比如「D03.C1 亏本 SKU 漏了 X-123」） | 题目有区分度，判分器在工作 | ✅ 通过 |
| 分数 = 100，但**全程没有任何一个条件失败过** | 对被测模型来说这套题仍然太浅 | ⚠️ 难度不足，不算通过 |
| 分数 < 100，但失败原因是**歧义**（你认为自己的答案也对） | 题目有歧义 | ❌ 不通过，请把该题面 + 你的答案 + 你的理由发 issue |

### 5.5 请特别验证这三件事

1. **歧义**：有没有哪道题，你认为存在两个都合理的答案，但判分只认一个？
   （这是最伤的问题，比难度不足严重得多。）
2. **难度**：`R03`（背包，贪心会错）、`R04`（6 人 6 色零直述）、`C04`（双 bug 互相掩盖）这三道是不是真的需要动脑？
3. **判分是否真的在比对**：随便挑一道你答对的题，把答案改错一个字段，重判，分数必须下降。
   ```bash
   node scripts/cli.mjs regrade --run <runId> --answers <改坏后的答案文件>
   ```

## 6. 我们承诺不做的宣传

- ❌ 不说「跑满分 = 模型很强」
- ❌ 不说「全平台兼容」（macOS 仅测试层面验证，OpenClaw / Codex 未测）
- ❌ 不说「防作弊」（背固定答案无效是真的，但我们不承诺能防住有心的作弊者）
- ❌ 不拿 v1.2.0 的历史分数当 v1.3.0 的基准

---

**最后一句**：如果这套题在你的模型上也是满分且无任何失分点，那说明**题目还不够难**，
请告诉我们，我们继续加。这个项目的价值在于**可复核**，不在于给个好分数。
