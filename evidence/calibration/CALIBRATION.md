## 1. 实验设计与执行

### 1.1 三档策略定义（这是实验设计，不是作弊）

| 档位 | 作答纪律 | 预期落点 |
|---|---|---|
| 强档 careful | 每题逐条对照 `criteria`，检查边界条件（"超过" vs "不少于"、撤回、例外覆盖） | 接近满分 |
| 中档 normal | 只做主要推理，不回查细节；**固定三类疏漏**：漏掉"例外"分支、理由字段写得含糊、两步运算只算第一步 | 60–85 |
| 弱档 sloppy | 只看题面大意；容易沿用被覆盖的旧值、漏掉"撤回/例外/覆盖"、字段不全 | 20–55 |

三档的差异是**作答纪律**的差异，不是随机噪声：中档的三类疏漏在每局都按同一规则触发，
所以同一个 seed 在不同档位下的分差是可解释的（能指到具体哪个 check 掉了）。

## 6. 引擎缺陷证据（作废局，单独存档）

这一节不是校准统计的一部分，而是「真实考试把引擎 bug 抓出来」的证据，保留原样。

### 6.1 C04 判分器崩溃 → 整局 SYSTEM_ERROR

- run：`run-20261029-163602-7b7826`（seed `cal-strong-1`，作废）
- 现象：C04 三条件全部 `SCORER_ERROR`，reason 均为 `评分器内部异常：rc is not defined`
- 后果：`summary.status = SYSTEM_ERROR`、`summary.level = null`、总分 73 但**无法给段位**
- 根因：`src/exam/items/correction.mjs` 的 `grade()` 里引用了未定义变量 `rc`（应为 `rcRaw`）
- 影响面：**该版本下所有考生 C04 恒 0 分（9 分）**，且整局无法评级
- 证据文件：`qa/calibration/aborted/cal-strong-1.report.json`、`aborted/cal-strong-1-b4-submit.log`

### 6.2 R04 题面缺第 4 个人名

- 现象：prompt 只列出 3 个名字（如"阿布、阿金、阿海"），但判分要求 4 人全对
- 后果：该题**理论上限 6/9**，任何按题面作答的人都拿不到 C1/C3
- 证据：`aborted/cal-strong-1-b4.aborted.json` 中的失败理由「3/4 人位置正确；未解析到：阿豆」
- 修复后（当前版本）R04 满分可达，本报告 §4 的 R04 数据全部来自修复后版本

## 7. 结论

### 7.1 是否达到产品目标

| 目标 | 实测 | 结论 |
|---|---|---|
| p50 ≤ 180s | **73.6s** | ✅ 达成（余量 106s） |
| p90 ≤ 300s | **200.2s** | ✅ 达成（余量 100s） |

**但要注意**：p90 的 200.2s 来自强档（逐条核对 criteria 最费时）。
如果产品目标是"普通用户随手跑一局"，参考中档的 53–95s 更合适。
若未来引入更慢的模型（真实 API 延迟），p90 会显著上升 —— 本数据不含任何网络等待。

### 7.2 题库要不要调

**要调，但不是"整体太难/太易"，而是三处结构性失衡：**

1. **R02 过易（96%）**：拓扑序题给的依赖图几乎线性，没有真正的分支选择。
   → 建议：加入"两个步骤可互换但只有一个满足某附加约束"的设计，或把 D 的依赖改为"B 或 C 之一完成即可"制造分支。
2. **D03 过易（93%）**：两表合并在 9 个 SKU 规模下太直接。
   → 建议：加大到 15+ SKU，并加入"同一 SKU 在供应商表出现两次（不同批次价）"需要取最新价的规则。
3. **D02 区分度失效（11pp）**：题目设计很好（考"信息不足"），但 `D02.C2` 要求理由里出现特定措辞（"缺失"/"预算不等于"），
   导致**答对了但话说得不一样**就丢 2 分，噪声淹没了信号。
   → 建议：C2 改为语义等价判定（提供同义词表），或把它降为 1 分、把 C1 提到 4 分（结论比措辞重要）。
4. **C04 区分度低（11pp）**：弱档只要根因对+小计对就能拿 6/9，忘记乘折扣只丢 3 分。
   → 建议：把 C3（乘折扣）从 3 分提到 4 分，或增加"round 边界"子条件（如 0.5 进位方向）。

**不建议动的**：I02、C01、C02、D04、C03 —— 这五题区分度 67–89pp，是题库的骨架。

### 7.3 一个必须说清楚的方法论局限

- **n=3/档位太小**。三档中位数分别是 96 / 83 / 57，但每档只有 3 个样本，
  单局波动可达 ±10 分（弱档 36→64 就是例子）。这些数字**足以判断"有没有区分度"，不足以精确估计"平均分是多少"**。
- **"弱档"不等于"低能力模型"**。sloppy-1 拿了 64 分（基础段位），说明这套题对"粗心但基础扎实"的作答者仍然友好。
  如果要测真正的弱模型，需要真的换模型，而不是继续压低作答质量。
- **耗时含人工阅读时间**。我读题、推理、写答案的时间全算在内，所以它是"Agent 完整跑一局"的上界，不是"引擎开销"。
  引擎本身的判分开销见 `PERF.md`（毫秒级）。
