怎么装，怎么跑完一场

唯一的前置条件是 Node.js ≥ 18.17。没有 npm install，没有运行时依赖， 也不需要联网。下面三种安装方式分别标了我们实际验证到哪一步 —— 没验证的部分会直接写「未实测」。

前置条件

运行前置条件
项目要求说明
Node.js≥ 18.17.0仓库里没有运行时依赖，不执行 npm install。
操作系统Windows / macOS / LinuxWindows 全流程实测通过；另两个平台有实现分支，未真机跑完整局。

先确认一下版本：node --version。低于 18.17 会在启动时报错，doctor 也会明确标出这一项。

三种安装方式

方式 A · 用户级 Skill 目录 VERIFIED

装到 ~/.agents/skills/lezi-bench/。这是本次唯一被证实「DSH 真的扫描到了」的安装方式： 装完后本会话的 skill 目录里直接出现了 lezi-bench 这一条，可以像其他 Skill 一样被触发。 

# 1. 拿到仓库
git clone https://github.com/tbj0623/lezibench.git
cd lezibench

# 2. 同步成一个可安装的 Skill 包，并做全量哈希校验
node scripts/sync-skill.mjs --target ~/.agents/skills/lezi-bench

目录名必须是 lezi-bench，不是 lezibench

Agent Skills 规范要求 frontmatter 的 name 与父目录名完全一致， 本 Skill 的 name 是 lezi-bench。装成 lezibench/ 目录会被静默跳过， 而且模型端无法区分「不存在」和「存在但非法」 —— 只会看到目录里少了这一条。

验证安装是否成功：新开一个会话，确认 skill 目录里有 lezi-bench； 或者直接在装好的目录里跑一次 node scripts/cli.mjs doctor，五项全 ✔ 就说明包是完整的。

方式 B · 工作区级 Skill 目录 结构与可执行已验证

装到 <projectRoot>/.agents/skills/lezi-bench/。DSH 的扫描根里项目级排在用户级前面 （rank 200 vs rank 500），适合「跟着仓库走、不想污染用户目录」的场景。 

node scripts/sync-skill.mjs --target .agents/skills/lezi-bench

验证到哪一步：这个路径结构合规、安装后的包能通过 doctor； 但我们没有做「只留工作区级、删掉用户级」的隔离实验，所以无法单独证明是这一条被加载。 优先级规则本身见 PLATFORM_NOTES §2.2。

注意：projectRoot 取的是最近的含 .git 的祖先目录；没有 .git 时退回当前工作目录。

方式 C · 不安装，直接在仓库里跑 VERIFIED

不需要任何安装步骤。克隆下来，直接在仓库根目录执行 node scripts/cli.mjs … 即可。 没有 Skill 触发的便利，但完全不依赖宿主的 skill 扫描机制 —— 也是本次实测里最省事的一条。 

git clone https://github.com/tbj0623/lezibench.git
cd lezibench
node scripts/cli.mjs doctor
node scripts/cli.mjs start --mode standard --json

方式 D · npm bin / npx 未实测

未实测 — 请勿照抄

package.json 里确实声明了 "bin": { "lezi-bench": "scripts/cli.mjs" }， 但 npm install、npm link、npx 这三种调用方式 本次一次都没有执行过，wrapper 在 Windows 下的行为也没有验证。

所以我们不写npx lezi-bench 可用。等有人真的跑通了，再补进这一节。 在此之前，请用上面的 A / B / C。

完整开考流程

所有命令都在 SKILL.md 所在目录执行（也就是安装出来的 lezi-bench/ 目录）。 下文用 node scripts/cli.mjs；如果你的宿主要求绝对路径，就用该目录拼接。

  1. 环境自检

    node scripts/cli.mjs doctor

    期望五项全 ✔，最后一行是「全部通过，可以开考。」。 有任何一项 ✘ 就停下来，把具体缺什么如实告诉用户 —— 不要带着坏环境硬跑。

  2. 开始一局，拿第 1 批题目

    node scripts/cli.mjs start --mode standard --seed demo-2026 --json

    --seed 可省略，省略时用当前时间戳。指定 seed 的价值是可复现： 同 seed 生成同一套题面，方便对照排查。

    返回的 JSON 里，记下 runId（后面每条命令都要用），并注意这几项：

    • batch = 1，totalBatches = 4，totalQuestions = 16
    • items[]：本批 4 道题，每题带 id / points / prompt / criteria
    • progress：形如「第 1/4 批 · 已完成 0/16 题」

  3. 作答，写进一个 JSON 文件

    按 prompt 的要求作答；题面说「只输出一个 JSON 对象」时，答案就是那个对象。

    {
  "answers": {
    "I01": { "deadline": "周三下午2点", "budgetAttached": false },
    "R01": { "subtotal": 70, "total": 65 },
    "D01": { "list": ["南京", "苏州", "杭州"] },
    "C01": { "isCorrect": false, "correctTotal": 55 }
  }
}

    上面是格式示意，数值不是答案 —— 每局的日期、金额、名单都由 seed 生成，照抄必定错。

    • 外层 answers 可省，直接写 {"I01": …} 也可以。
    • 键必须是本批题目的真实 id，写别的批次会直接报错。
    • 值可以是 JSON 对象，也可以是 JSON 字符串；判分器会做等价归一。
    • 答案文件上限 256 KB。

  4. 提交本批

    node scripts/cli.mjs submit --run <RUN_ID> --batch 1 --answers-file answers-batch1.json

    输出会给出本批得分、逐题得分与失败条件的理由，以及下一批的 4 道题。

    • 看到 finished: true（文本模式下会直接打印总分摘要）说明四批都完了。
    • 看到 idempotent 说明这批用相同答案提交过，本次不重复计分，属正常。
    • 看到「拒绝用不同答案覆盖」说明这批已经判分了 —— 继续下一批或新开一局，不要尝试绕过。

  5. 重复三次

    node scripts/cli.mjs submit --run <RUN_ID> --batch 2 --answers-file answers-batch2.json
node scripts/cli.mjs submit --run <RUN_ID> --batch 3 --answers-file answers-batch3.json
node scripts/cli.mjs submit --run <RUN_ID> --batch 4 --answers-file answers-batch4.json

    每条命令带同一个 RUN_ID，--batch 依次 2 / 3 / 4。每批的题目 id 见上一批返回的 items[].id。

  6. 出报告

    node scripts/cli.mjs report --run <RUN_ID> --format html
node scripts/cli.mjs report --run <RUN_ID> --format summary

# 想自己指定输出位置：
node scripts/cli.mjs report --run <RUN_ID> --format html --out ./report.html

# 需要完整机器可读证据（含逐题 checks）：
node scripts/cli.mjs report --run <RUN_ID> --format json

    HTML 是自包含文件，命令会打印绝对路径，双击即可打开、断网也能看。 summary 是纯文本，适合直接贴进对话。

中途断了怎么办

状态全部落在磁盘上，不会因为上下文丢失而作废：

# 不知道做到哪了
node scripts/cli.mjs status --run <RUN_ID>

# 继续跑，它会直接给出下一批题目
node scripts/cli.mjs resume --run <RUN_ID>

# 怀疑判分器有问题：只重判，不碰原答案
node scripts/cli.mjs regrade --run <RUN_ID>

# 历史运行 / 版本
node scripts/cli.mjs list
node scripts/cli.mjs version

数据目录在哪

默认按平台选择，可用环境变量 LEZIBENCH_HOME 覆盖。

各平台默认数据目录
平台默认路径覆盖方式
Windows %LOCALAPPDATA%\LeziBench LEZIBENCH_HOME
macOS~/Library/Application Support/LeziBench
Linux$XDG_DATA_HOME/lezibench，未设置时 ~/.local/share/lezibench

临时指定一个数据目录（不影响已有运行）：

# macOS / Linux
LEZIBENCH_HOME=/tmp/lezi node scripts/cli.mjs doctor

# Windows PowerShell
$env:LEZIBENCH_HOME="D:\lezi"; node scripts/cli.mjs doctor

目录里会生成 runs/<runId>/，下面分 answers/、reports/、evidence/ 与 state.json。详见隐私说明。

常见故障

故障现象与处理
现象原因与处理
skill 目录里看不到 lezi-bench 目录名与 name 不一致，或目录层级超过一层。DSH 只扫一层，且坏掉的包会被静默跳过。确认目录是 <root>/lezi-bench/SKILL.md。
「批次不包含这些题目」 答案文件的键写错了批次。按当前批返回的 items[].id 修正后重交。
「已提交并判分，拒绝覆盖」 该批已判分且答案不同。这是设计上的保护，不要绕过；继续下一批或新开一局。
报告里出现「待复核」 有题目答案无法解析成任何标准字段，或判分器内部异常。此时整局状态为 PARTIAL，不给段位。用 status 看是哪几题，改规范格式后新开一局。
Node 版本过低 doctor 第一项会标 ✘。升到 18.17 或更高；本仓库没有 polyfill。
数据目录不可写 doctor 第四项会给出具体错误码。换一个可写目录：LEZIBENCH_HOME=<可写路径>。
